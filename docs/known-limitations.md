# 已知边界与后续方向 · vision-qc-agent

> 这份文件写给**技术评审和面试**：把当前实现的适用边界、已知误报来源、部署限制一次说清。
> README 面向"五分钟了解项目是什么"，不含本节内容。
> 每个条目都对应代码里的具体行为，不是免责声明。

---

## 1. 输入与格式边界

**JPEG / WebP 不做本地像素解码。**
零依赖前提下只实现了 PNG 解码（`src/image/inspect.mjs` 的 `decodePng`），所以 JPEG/WebP/GIF 的
「背景白度」「主体色」「明暗离散度」等实测指标会缺失，相关规则降级为**未判定**并提示人工复核，
一致性检查的 ΔE 比对也会跳过。取舍很明确：**宁可说"不知道"，也不猜一个数字。**
换成引入 `sharp` / `canvas` 能解决，但会打破"零运行时依赖、`npm start` 免安装"这个卖点。

**样例图是矢量风渲染图。**
`samples/` 6 张由无头 Chrome 渲染 HTML 生成（`scripts/make-samples.mjs`），不是真实商品照，
所以「细节不可辨识」「色差风险」这类判断在样例上偏严格。换成实拍图会更接近真实场景。

## 2. 判定与模型边界

**单图色差判断仍是模型主观项。**
真正的色差需要色卡和标准光源；单张图里它只是"风险提示"，不构成测量结论。
只有**组内**色差才用得上实测 ΔE。

**ΔE 假设主体色可以用一组平均 RGB 代表。**
花色、渐变、多色拼接的面料会被平均成一个中间色，这时 ΔE 偏大属于误报。
目前靠「模型与实测冲突」提示人工复核兜住；更严谨的做法是比色直方图（EMD / JS 散度）而不是均值。

**单次采样的边界会翻盘。**
实测同一张 1000×1000 的 `01-perfect-white.png`，两次调用分别得到 `88 需优化` 和 `87 不合格`：
分数只差 1，差别在于第二轮 `R05 主体占比`（medium）由通过变不通过（实测 55%），
medium 失败累计到 3 条，触发「三条 medium 即不合格」。
根因是模型单次采样的方差（`productCoverage` 来自模型输出）。
（原始报告在开发机 `reports/` 下，按 `.gitignore` 不入库；`node src/cli.mjs samples --save`
可跑出同结构的报告自行复核。）
两种修法：把 `temperature` 降到 0（现为 0.1），或对临界样本跑 2–3 次取多数（成本翻倍，只对边界图触发）。

**模型不回事实字典时按「未判定」处理。**
模型偶尔把枚举答成 `"None"`、布尔答成 `"false"` 字符串。这类值先按 `src/core/facts.mjs` 归一化
（大小写 / 空白 / 中英文同义），无法归一的一律丢弃，让规则落到「未判定」而不是伪造一条「不通过」；
被丢弃的字段名会写进报告的 `model.normalized`。

**阈值建议只到「建议」为止。**
系统不自动改清单。静默按反馈放宽标准，最后会得到一条什么都通过的规则 —— 这是刻意的产品决定，
不是没做完。

## 3. 一致性与成本边界

**一致性检查是整组一次调用。**
图片多了会顶到上下文与成本上限（当前单批上限 12 张）；也还没做「跨批次」的 SKU 一致性 ——
同一商品分两次上传，不会互相比对。

**峰谷价按单次请求时刻计。**
一次跑批跨过高峰/错峰边界时不会拆分计价，误差上限为单批的一半。

**OpenAI 费率未经官方核实。**
构建环境访问不到其定价页，`src/core/pricing.mjs` 里那几行已明确标注 `unverified`，
用前请对照官方页面自查。DeepSeek 一栏有官方来源与核对日期。

## 4. 运行与部署边界

**推翻日志是本地文件、无并发写保护。**
`data/feedback.jsonl` 是 append-only 文件，适合单机演示；多人协作要换成带锁的存储（SQLite/Postgres）。
推翻记录已按「图片名 + 清单 id」隔离，避免规则编号在各清单间重复导致串味。

**推翻日志会让演示分数漂移。**
同一个文件里的推翻会一直作用于同名图片，所以带着历史记录重跑 `samples/` 得到的分数，
与 README §12 的首次结果不同（那是预期行为，不是 bug）。
想回到初始状态：`rm data/feedback.jsonl`，不存在其他隐藏状态。

**没有做鉴权。**
服务只监听 `127.0.0.1`，定位是本地演示。对公网或内网开放前必须先补鉴权、限流与上传隔离。

**DSH 集成需要重启 GUI 或等它热加载。**
补丁写入 `~/.dsh/profiles/web/cordis.patch.yml` 后，工具在 DSH 重新加载后才会出现在工具列表里。

## 5. 后续方向（如果继续做）

1. **跨批次一致性与 SKU 归档**：把同一商品的多次质检结果聚合成 SKU 视图，而不是每次独立成批。
2. **色差改成直方图比对**（EMD / JS 散度）替代均值 ΔE，解决花色面料的误报。
3. **推翻记录驱动清单演化**：把建议产成 PR / 补丁而不是一段文字，人工点确认即可生效。
4. **视频 / 直播流抽帧质检**：同一套事实模型迁移到动态素材。
5. **成本护栏**：批量前预估花费，超过预算阈值先停下让人确认（`qc_cost_estimate` 已有基础）。
